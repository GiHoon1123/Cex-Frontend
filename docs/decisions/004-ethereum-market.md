# ETH/USDT 거래 화면

기존 BTC/USDT 거래 화면에 ETH/USDT 선택을 추가하고, 선택한 시장의 별도 플랫폼 WebSocket·차트·주문 원본을 사용한다.

## 문제와 기존 동작

엔진 자료구조와 플랫폼 시세 저장은 거래쌍을 구분하지만 프론트는 BTC 문자열과 소켓 경로를 고정했다. 화면 표시만 바꾸면 주문은 BTC로 제출되는 위험이 있어 연결·검증·주문 원본을 같은 선택 상태에 묶어야 했다.

## 기존 제품과 공식 자료의 접근

거래 화면의 시장 선택은 선택한 거래쌍이 호가·체결·차트·주문 입력 전체에 적용되는 방식을 따른다. 시각 구성은 기존 바이낸스 다크 기준을 유지하고 새 디자인 체계를 만들지 않았다.

## 선택과 트레이드오프

현재 지원 자산을 `BTC | ETH`의 TypeScript 유니온으로 명시했다. 서버의 임의 자산 목록을 그대로 렌더링하는 것보다 새 자산 추가 때 코드 변경이 필요하지만, 입출금·정밀도·규제 경계가 준비되지 않은 자산을 실수로 노출하지 않는다. 시장을 바꾸면 기존 화면 상태를 즉시 지우고 새 소켓에 연결한다.

## 구현과 관련 코드

[MarketContext.tsx](../../apps/exchange/src/contexts/MarketContext.tsx)의 일부다.

```typescript
const setBase = (next: BaseAsset) => {
  setView(null);
  setConnected(false);
  setBaseState(next);
};
```

기존 BTC 호가가 ETH 화면에 잠시 남지 않게 먼저 비운다. `acceptSnapshot`도 예상 기준 자산과 결제 자산을 받아 다른 시장 프레임을 거부한다. 주문 패널은 같은 `base`를 `baseMint`와 잔액·수량 단위에 사용한다.

## 이해에 필요한 문법과 원리

`'BTC' | 'ETH'`는 허용 문자열을 컴파일 시점에 제한하는 유니온 타입이다. 런타임 WebSocket 입력은 타입을 신뢰할 수 없으므로 별도의 구조·거래쌍 검사를 계속 수행한다.

## 작성한 테스트

- `tests/contracts.test.ts`의 `선택한 이더리움 시장만 화면 상태로 받는다`: ETH 프레임 허용과 BTC 화면의 ETH 프레임 거부를 확인한다.
- 같은 파일의 공개 소켓 검사는 ETH 경로 생성을 확인한다.
- `e2e/exchange.spec.ts`의 `이더리움 시장을 선택하면 별도 호가 연결과 주문 원본을 사용한다`: ETH 소켓, 호가 제목, 수량 단위, 주문 `baseMint=ETH`를 브라우저에서 확인한다.

## 실행 명령과 결과

계약 12개, ESLint, 고객·운영자 앱 빌드가 통과했다. 브라우저 검사는 처음에 데스크톱·모바일용 동일 레이블 두 개를 엄격 선택해 1건 실패했고, 현재 화면 크기의 첫 선택기를 명시하도록 테스트를 고쳤다. 재실행에서 기존 5개와 새 ETH 시장 1개, 총 6개가 통과했다.

## 관련 커밋과 참고 자료

플랫폼 거래쌍별 소켓 커밋과 함께 읽는다. ETH 온체인 입출금 완료를 의미하지 않는다.
