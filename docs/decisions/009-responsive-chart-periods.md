# 좁은 화면을 복구하고 차트 기간을 선택하기

320px 화면에서 헤더와 시장 선택기가 줄바꿈되거나 거래 영역을 밀어내는 문제를 고치고, BTC·ETH 차트에서 분봉·시간봉·일봉을 선택하게 한 과정을 설명한다.

## 문제와 기존 동작

모바일 상단은 `BTC/USDT` 제목과 같은 값의 선택기를 나란히 표시해 공간을 중복 사용했다. 320px에서는 브랜드, 로그인, 회원가입 문구가 여러 줄로 갈라졌고 주문 탭은 최근 체결과 주문 폼을 좌우 절반씩 나눠 입력 영역이 지나치게 좁았다. 차트는 1분 봉 하나만 제공해 긴 흐름을 볼 수 없었다.

## 기존 제품과 공식 자료의 접근

Binance 거래 화면처럼 차트 위에 짧은 시간 간격 버튼을 두고 선택한 간격만 강조한다. [Binance Spot Kline API](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints#klinecandlestick-data)가 지원하는 간격 가운데 현물 화면에 필요한 `1m`, `5m`, `15m`, `1h`, `4h`, `1d`, `1w`, `1M`을 선택했다. API 전체 간격을 그대로 노출해 화면을 복잡하게 만들지 않았다.

## 선택과 트레이드오프

각 간격은 최대 최근 500봉을 사용한다. 실제 개수는 Binance 상장 이력을 넘지 않으므로 현재 응답은 주봉 481개, 월봉 111개다. 요청 수와 화면 복잡도는 일정하지만 시간 범위는 간격에 따라 약 8시간부터 전체 월봉 이력까지 달라진다. 시작·종료 시각을 자유 입력하는 방식은 정확한 분석 범위를 주지만 추가 페이지 조회, 최대 조회량, 시간대 입력 검증이 필요하므로 현재 거래 화면에는 넣지 않았다.

모바일 헤더 메뉴를 숨기지 않고 패딩과 짧은 명칭을 사용했다. 기능 접근성은 유지되지만 `거래내역`은 작은 화면에서 `내역`, `마이페이지`는 `자산`으로 보인다. 주문 탭은 640px 미만에서 최근 체결과 주문 입력을 세로로 쌓는다. 한 화면에 보이는 체결 행은 줄지만 입력 폭은 304px로 복구된다.

## 구현과 관련 코드

[MarketChart](../../apps/exchange/src/components/MarketChart.tsx)의 간격 목록은 플랫폼 허용 목록과 같다.

```ts
const intervals:[CandleInterval,string][]=[
  ['1m','1분'],['5m','5분'],['15m','15분'],
  ['1h','1시간'],['4h','4시간'],['1d','1일'],
  ['1w','1주'],['1M','1개월']
];
```

버튼을 바꾸면 이전 요청을 취소하고 `interval` 쿼리와 응답값이 같은지 검사한다. 새 응답 전에는 이전 봉을 현재 선택처럼 남기지 않는다. 주봉·월봉을 더한 기간 버튼은 320px에서 두 줄로 접어 모든 선택지를 화면 안에 노출한다.

[거래 화면](../../apps/exchange/src/app/page.tsx)은 중복 시장 제목을 제거하고 선택기 하나만 남겼다. 주문 영역은 작은 화면에서 두 행, 640px 이상에서 두 열이 된다. [Header](../../apps/exchange/src/components/Header.tsx)는 320px에서도 브랜드와 인증 버튼을 한 줄로 유지한다.

## 작성한 테스트

- `e2e/exchange.spec.ts`의 `플랫폼이 중계한 Binance 기준 봉을 그리고 브라우저가 Binance를 직접 호출하지 않는다`
  - 여덟 간격을 차례로 선택하고 각각 올바른 `interval` 쿼리가 플랫폼으로 전달되는지 확인한다.
- `e2e/exchange.spec.ts`의 `작은 화면에서도 헤더·시장 선택·차트 기간·주문 영역이 겹치지 않는다`
  - 320×720, 375×812, 768×900, 1024×768, 1440×900을 검증한다.
  - 문서 가로 넘침, 헤더 요소 경계, 시장 선택기 경계, 월봉 버튼 노출을 확인한다.
  - 모바일 주문 입력 폭이 320px 화면에서 296px 이상인지 확인한다.

## 실행 명령과 결과

```text
npm run lint      통과
npm run test:e2e  9개 통과
```

실제 Chrome에서 다섯 화면 폭을 캡처하고 문서 너비가 화면 너비와 같은지 확인했다. 320px에서 시장 선택기는 113px, 주문 입력은 304px였고 여덟 기간 버튼이 두 줄 안에 표시됐다. BTC 월봉을 포함한 실제 Binance 응답도 플랫폼을 통해 렌더링했으며 브라우저의 Binance 직접 요청은 0건이었다.
