# 프론트 연결 검증 중 발견한 Next 의존성 갱신

실제 설치 의존성 감사가 Next 16.0.8을 취약 버전으로 보고해, 같은 16 버전 계열의 수정 버전으로 갱신하고 화면·접수 검증을 다시 수행했다.

## 근거와 선택

2026-10-21 `npm audit --json`은 전체 의존성에서 20개 패키지 보고를 반환했다. 그중 Next는 심각 단계였다. [유지보수자의 AVIF 이미지 최적화 보안 공지](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4)는 16.3.3 이전 버전을 영향 범위로 명시한다. 실제 공격 성공을 재현한 검증은 아니다.

설치 가능한 [Next 16.4.2 공식 릴리스](https://github.com/vercel/next.js/releases/tag/v16.4.2)와 내장 업그레이드·Strict Mode·Playwright 문서를 확인했다. Next와 공식 ESLint 설정을 함께 16.4.2로 고정하고, 설치된 허용 범위 안에서 나머지 수정 가능한 전이 의존성을 갱신했다. 프레임워크의 실행·개발 동작 변경 가능성을 감수하는 대신 알려진 취약 버전을 유지하지 않는다.

`npm audit fix`가 제안한 강제 메이저 변경은 실행하지 않았다. 새 버전이 생성하는 `AGENTS.md`에는 공통 작업 규칙 링크를 추가하고 설치된 버전의 내장 문서를 읽도록 한 생성 블록을 보존했다.

## Strict Mode와 소켓 회귀

개발 모드에서 효과를 생성·정리한 뒤 다시 생성하는 동작을 재검증했다. [시장 컨텍스트](../../src/contexts/MarketContext.tsx)는 정리된 연결의 늦은 메시지·종료 콜백을 무시하도록 보완했다. [브라우저 테스트](../../e2e/exchange.spec.ts)는 최초 연결 번호를 가정하지 않고 현재 활성 연결과 이후 재연결을 확인한다.

## 실행 결과

```sh
npm audit --json
npm audit --omit=dev --json
npm run lint
npm test
npm run test:e2e
NEXT_DIST_DIR=.next-market-build npm run build
```

2026-10-21, Node 22.22.3·기존 Chrome 기준:

| 검증 | 결과 |
| --- | --- |
| 운영 의존성 감사 | 보고 0개 |
| 전체 의존성 감사 | 개발 도구 경로의 높음 5개 남음 |
| 린트·타입 검사·제품 빌드 | 통과 |
| 계약 테스트 | 11개 통과 |
| 브라우저 테스트 | 3개 통과 |

남은 보고는 공식 ESLint 플러그인의 `fast-glob`·`micromatch`·`braces` 경로와 해당 상위 패키지다. 설치·감사 시점의 잠금 파일과 도구 보고를 기준으로 기록했다. 감사 0개인 운영 의존성도 취약점이 존재하지 않음을 증명하는 것은 아니다. 개발 도구 보고의 해소 여부는 후속 갱신에서 다시 확인한다.

기존 로컬 3003 서비스를 재시작하거나 배포한 결과가 아니다. 검증용 포트·빌드 경로와 예약 도메인의 모의 플랫폼을 사용했다. 프론트 연결 기능의 자세한 검증은 [BTC 연결 기록](001-platform-market-and-btc.md)을 따른다.
